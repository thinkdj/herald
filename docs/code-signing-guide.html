Windows Code Signing

The landscape changed dramatically in 2024. Do not overpay for EV.

Key change (2024): EV certificates no longer bypass SmartScreen. Both OV and EV now go through the same reputation-building process. Paying extra for EV solely for SmartScreen is no longer justified.
Hardware mandate (June 2023): CAs can no longer issue OV/EV certs as exportable .pfx files. All new certs must live on HSMs or cloud HSM equivalents (Azure Key Vault, SSL.com eSigner, etc.).
Feb 2026: Max cert validity capped at ~15 months (458 days).

Hardware Token vs Cloud Signing: Why It Matters for CI/CD

Since June 2023, all new code signing certs must live on HSMs. For automated CI/CD builds, you need cloud-based signing because a physical USB token can't plug into a GitHub Actions runner. Certum's SimplySign and SSL.com's eSigner both offer API-based signing that works in CI. If you go with a reseller that ships a physical token, you'd need to sign locally after downloading CI artifacts. Doable, but clunky.

Individual vs Organization Certs

Individual certs (OV Individual or IV) show your legal name as the publisher, not a brand or trade name. If you want a company name as publisher, you need an OV organization cert, which requires a registered business entity. The cert itself can be cheaper (~$116/yr from Certum), but the business registration overhead is the real cost.

SmartScreen Reputation

With any cert type, first-time users will see "Windows protected your PC." Reputation builds organically as users download and run the app. There is no shortcut; you just need real download volume. Signing is still essential: unsigned apps get a much harsher dialog that most users won't click through.

macOS Signing & Notarization

Straightforward: one $99/yr membership covers everything.

  • Apple Developer Program: $99/yr. Gives you Developer ID certificates (for distribution outside App Store) and free, unlimited notarization.
  • Notarization: Apple scans your app for malware and stamps it. Without this, Gatekeeper blocks your DMG. Process is automated in CI.
  • Universal binary: Tauri can build both aarch64-apple-darwin (Apple Silicon) and x86_64-apple-darwin (Intel) targets.
  • You don't need a Mac to sign: the GitHub Actions macOS runner handles signing + notarization in CI. You just need the cert + credentials as GitHub Secrets.

Tauri's CI integration passes Apple cert + notarization credentials as environment variables. The tauri-apps/tauri-action handles the rest.

Linux Distribution

No paid certificates. No gatekeeper. The easiest platform.

Build on ubuntu-22.04 to keep the glibc floor low. Tauri produces AppImage and .deb by default.

AppImage: portable, runs on most distros without install. Optional GPG signing (free, your own key).

.deb: for Debian/Ubuntu users who prefer apt.

Flatpak/Snap: adds store review overhead. Add when users ask.

.rpm: add when Fedora/RHEL users appear.

Automated Build & Release

GitHub Actions + tauri-apps/tauri-action handles the heavy lifting.

What to set up

  1. A release workflow triggered by tag push (v*) that builds on all three platforms via matrix strategy using tauri-apps/tauri-action
  2. Inject Apple signing secrets into macOS build job: APPLE_CERTIFICATE, APPLE_CERTIFICATE_PASSWORD, APPLE_ID, APPLE_PASSWORD, APPLE_TEAM_ID
  3. Inject Windows signing into Windows build job: cloud signing API credentials (Certum SimplySign, Azure Trusted Signing, or signtool + cloud HSM)
  4. Generate Tauri updater keypair with tauri signer generate and set the public key in tauri.conf.json
  5. Store the updater private key as TAURI_SIGNING_PRIVATE_KEY and password as TAURI_SIGNING_PRIVATE_KEY_PASSWORD in GitHub Secrets
  6. Wire your update feed (GitHub Releases JSON, or a custom updater server) to serve latest.json for the Tauri auto-updater

Updater Signing

Separate from OS code signing. Tauri verifies updates with its own keypair.

Tauri's updater plugin uses minisign, a lightweight signature scheme. The flow:

  • Generate Run tauri signer generate -w ~/.tauri/myapp.key locally. Save the password. This creates a keypair.
  • Configure Paste the public key into tauri.conf.json → plugins.updater.pubkey.
  • CI Secret Store the private key as TAURI_SIGNING_PRIVATE_KEY and the password as TAURI_SIGNING_PRIVATE_KEY_PASSWORD in GitHub Secrets.
  • Build tauri-action automatically signs update bundles (.sig files alongside each artifact) when these env vars are present.
  • Verify The app checks signatures against the embedded public key before applying any update.

Implementation Order

Do this in order. Each step is independently shippable.

  • Week 1: Updater keypair Generate minisign key, set pubkey in tauri.conf.json, add secrets to GitHub. Zero cost, unblocks signed updates.
  • Week 1: Apple Developer Program Enroll at developer.apple.com ($99). Takes 24–48 hrs to process. Export cert, add to GitHub Secrets.
  • Week 2: macOS signing in CI Add Apple env vars to your release workflow's macOS job. Test a tag push. macOS builds now signed + notarized.
  • Week 2-3: Windows signing Sign up for your chosen cert provider. Identity verification takes a few days. Configure cloud signing in your release workflow's Windows job.
  • Week 3: Update feed Wire your updater endpoint to serve signed artifacts + latest.json after each release.
  • Week 4: First signed release Tag v1.0.0. All three platforms build, sign, upload. Auto-updater serves the feed. Ship it.
The short version: ~$305/yr (or $120/yr if eligible for Azure Trusted Signing) gets you signed builds on all platforms with automated CI/CD. Most of the work is injecting signing credentials into your GitHub Actions workflow and generating a Tauri updater keypair.
